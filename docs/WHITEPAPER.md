# Potify ID
## Whitepaper · public developer edition

**November 25, 2026 · Two-app pilot and website integration source**

### Goal and audience

Let someone carry credit for a contribution from the Greenhouse to a creator screening. The immediate audience is independent creators and platform engineers.

### Design and implementation

A fixture maps proven wallets to a single member, derives app-specific subjects, tracks grants and redeems a single-use attendance pass. Public keys can change and a person can hold several. The pilot uses a stable member with different subject identifiers for each app. Explicit consent controls the disclosed badge.

### What a contributor can establish

Eight local scenarios passed using disposable keys and two fixture applications. No partner-operated sign-in or physical-wallet check was performed. A screenshot of a badge cannot establish a reusable integration. A separate organizer must verify an expiring pass, enforce one use and report the result.

### Evidence and outstanding work

Local two-app tests and actual website branch source are verified. A deployed issuer, recovery on iPhone and independent partner adoption remain outstanding. The next acceptance case is concrete. Complete both test apps, revoke one grant and confirm that a check-in pass cannot be redeemed twice.

### Place in POTIFY

Seek one paid onboarding engagement only after an organizer confirms the integration and a live acceptance test passes. The marketing plan gives the test window and the evidence for a commercial outcome.
